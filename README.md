基于 Pyrogram MTProto 框架的 **Telegram 文件下载机器人**。不用挂着 Telegram 客户端，也不用敲命令行，把链接或文件发给机器人，就会下载到你的服务器或本地，单文件最大 **4GB**。

项目里每个文件的职责和架构图见 [STRUCTURE.md](STRUCTURE.md)。

---

## 🌟 核心特性

- 🚀 **大文件高速下载**：走 MTProto 原生协议，不受 Bot API 20MB/50MB 限制，单文件最大 **4GB**。
- 📊 **实时进度**：百分比、已下载大小、下载中近窗口实时速度、完成后全程均速、剩余时间。
- 🛑 **随时取消**：下载通知自带停止按钮；停止会放弃任务并删除已下载部分，断点续传只覆盖自动中断。
- 🔒 **受保护内容**：配置用户账号后，`/add` 能直接下载禁止转发的私有频道文件。
- 📡 **频道监听**：`/listen` 监听频道，新帖自动下载到独立文件夹，带广告过滤，结果按频道聚合通知。
- 🗂 **队列与文件管理**：`/queue` 查看和取消任务，`/pause` `/resume` 暂停恢复（进行中的会停下并保留断点），`/files` 浏览和删除文件。任务实时落盘，重启自动恢复断点；磁盘写满自动暂停并保留断点，清理后 `/resume` 继续。
- 📁 **子目录管理**：`/use` 随时切换保存目录。
- 💾 **磁盘查询**：`/usage` 查看磁盘总容量、已用和剩余空间。
- 🛡️ **管理员鉴权**：白名单支持用户名和数字 ID。
- 🌐 **代理连接**：支持 HTTP 和 SOCKS5 代理。
- 🖥️ **网页面板**：浏览器里改配置，保存即生效；桌面端可在连接设置下方查看下载队列并暂停、恢复、取消任务。

## 📋 前置准备

1. **API ID 和 API Hash**：到 [My Telegram] 官网，在 API development tools 里创建应用获取。
2. **Bot Token**：找 [@BotFather] 创建机器人后获取。
3. **手机号**：频道监听必填。下载和监听都由这个用户账号完成，机器人只负责交互，不填就用不了频道监听。

## ⚙️ 环境变量配置

配置在网页面板里填，保存后写入 `config/settings.env`，也可以直接用系统环境变量。

| 环境变量 | 必填 | 默认值 | 说明 |
| :--- | :---: | :---: | :--- |
| `TELEGRAM_API_ID` | **是** | - | 从 [My Telegram] 获取的 API ID |
| `TELEGRAM_API_HASH` | **是** | - | 从 [My Telegram] 获取的 API Hash |
| `BOT_TOKEN` | **是** | - | 从 [@BotFather] 获取的机器人 Token |
| `ADMINS` | **是** | 空 | 管理员白名单，用**空格**分隔，支持 `@用户名` 或 `用户ID`，如 `@username 12345678` |
| `PHONE_NUMBER` | 否 | 空 | 用户账号手机号，带国际区号，如 `+8613800000000` |
| `DOWNLOAD_FOLDER` | 否 | `/data` | 文件下载保存目录 |
| `CONFIG_FOLDER` | 否 | `/config` | 登录会话文件保存目录 |
| `PROXY` | 否 | 空 | 访问 Telegram 的代理，支持 `socks5://127.0.0.1:7890`、`http://127.0.0.1:7890`；要账号密码就写成 `socks5://user:pass@host:port`，只填 IP 和端口默认按 SOCKS5 处理 |
| `MAX_CONCURRENT_DOWNLOADS` | 否 | `3` | 同时下载的最大文件数 |
| `DEBUG` | 否 | 空 | 非空即开启详细调试日志 |

## 🚀 启动方式

本机装好 Python 3.13 后：

```bash
pip install -r requirements.txt
python start.py
```

浏览器打开 http://127.0.0.1:8080 ，填入 API ID、API Hash、Bot Token 和管理员，需要代理就填，例如 `http://127.0.0.1:7890`，点「保存并生效」。下载文件在 `data/`，登录会话和面板配置在 `config/`，运行日志按天写在 `config/logs/YYYY-MM-DD.log`（默认保留 30 天）。填了手机号的话，验证码会直接出现在网页里。

### Docker

直接用已发布的镜像最省事。新建一个目录，放入 `docker-compose.yml`：

```yaml
services:
  tg-bot-dl:
    image: guyongbo/tg-bot-dl:latest
    container_name: tg-bot-dl
    restart: unless-stopped
    ports:
      - "8080:8080"
    volumes:
      - ./data:/data
      - ./config:/config
    environment:
      TZ: Asia/Shanghai
    extra_hosts:
      - "host.docker.internal:host-gateway"
```

启动：

```bash
docker compose up -d
```

浏览器打开 http://127.0.0.1:8080 填写配置。下载文件在 `./data`，登录会话和面板配置在 `./config`，日志在 `./config/logs`。容器里代理填 `127.0.0.1` 会自动改写成宿主机地址 `host.docker.internal`。

也可以用 GitHub Container Registry 的镜像：`ghcr.io/kuke2733/tg-bot-dl:latest`。

## 🤖 机器人使用指南

### 按起止消息链接批量下载

```text
/range https://t.me/频道用户名/100 https://t.me/频道用户名/150
/range https://t.me/c/1234567890/100 https://t.me/c/1234567890/150 我的收藏
```

下载同一个频道或群组中编号 **100～150（包含两端，共 51 个消息编号）** 的可下载媒体。支持图片、视频、普通文件、音频、语音、动画、视频消息和贴纸；文字、网页预览、投票、已删除或不可见消息会跳过。相册按每个文件自己的消息编号读取，不会扩展到范围以外的文件，也不会自动下载帖子的评论。

起止链接可以反向填写，程序自动按较小到较大的编号处理。公开用户名链接和私有数字链接会解析为真实会话 ID，确认属于同一会话；两个不同频道或群组的链接会被拒绝。论坛话题链接的编号范围按整个群组解释，不额外按话题筛选。

需要在面板完成用户账号登录，该账号必须能访问源频道或群组。每次最多读取 100 个消息编号，扫描完成后将媒体统一加入一个独立文件夹批次（默认 `范围_会话ID_起始编号-结束编号`），沿用队列、进度、查重和断点续传。扫描出错时不把部分结果加入队列；扫描阶段中途重启需重新发送命令。Telegram 中的 `/queue` 和网页下载队列均显示一条文件夹任务。网页暂无提交范围链接的输入框，请向机器人发送命令。

### 下载帖子评论区的图片和视频

在配置面板填写手机号并完成用户账号登录后，向机器人发送：

```text
/comments https://t.me/频道用户名/123
/comments https://t.me/c/1234567890/123 我的评论收藏
```

使用**频道原帖的消息链接**。程序定位该帖的关联讨论组线程，遍历已有评论（包括回复评论的消息和相册中的各个文件），只将真实图片、视频、动画及 MIME 类型为图片或视频的文档加入现有下载队列。文字、网页预览、投票、贴纸、音频和普通文档会被跳过。原帖自己的附件不会下载。

文件保存到当前目录下独立的 `评论_频道_帖子编号/` 文件夹，或者你指定的文件夹；只有一个文件时也使用独立文件夹。沿用原有进度、查重、暂停、取消和断点续传功能。扫描较多评论时会更新扫描进度，完成后显示批次文件夹和文件数；同时只允许一个评论扫描任务。

登录的用户账号必须有权读取原帖及关联讨论组，必要时先在 Telegram 中加入讨论组；本功能不会自动加入群组。未开启评论、无访问权限或扫描失败时会提示错误，不会把已扫描部分报告为完整结果。服务端限流时会等待后重扫并按消息去重，最多恢复 5 次。

此命令只扫描已有评论，不持续监听新评论。扫描期间新发或被删除的评论可能影响结果；扫描中途重启需要重新发送命令，已加入下载队列的文件沿用原有持久化机制。

#### NAS 构建包含本功能的镜像

上游发布的镜像不包含本地修改，使用源码目录中的专用 Compose 文件构建：

```bash
docker compose -f docker-compose.comments.yml up -d --build
```

默认使用源码目录下的 `./data` 和 `./config`。升级现有部署时请先备份并让卷挂载指向原来的目录；旧容器需先停止，避免同名容器、8080 端口或登录会话冲突。构建需要 NAS 能拉取基础镜像及 Python 依赖；机器人面板里的代理配置仅作用于机器人连接，不会自动代理 Docker 构建。

### 2. 发文件和重命名

把文档、视频、音频等任意媒体发给机器人，会自动加入下载队列。

重命名任选一种方式，**不用写后缀**，会自动补上：

1. **转发附带名字**：先发名字，紧跟文件
2. **回复进度消息**：回复后发新名字，比如 `电影`
3. **写在文件说明里**：说明里直接写 `电影`
4. **`/add` 命令**：`/add 链接 电影`

一次发多个文件会存进同一个文件夹，这时改名只改文件夹名，不改组内文件名；单个文件不建文件夹。

---

### 3. 下载受保护频道的文件

私有频道或群组开了「限制保存内容」后无法直接转发给机器人，操作如下：

1. 部署时配置了 `PHONE_NUMBER`，且该账号已加入目标频道；
2. 在频道里长按目标消息，点 **复制消息链接**，链接形如 `https://t.me/c/1234567890/123`；
3. 给机器人发送：

```text
/add https://t.me/c/1234567890/123
```

公开频道也行：

```text
/add https://t.me/频道用户名/123
```

想指定保存的文件名（不用写后缀）：

```text
/add https://t.me/c/1234567890/123 自定义名字
```

---

### 4. 频道监听自动下载

监听和下载都由用户账号完成，**机器人不用加入频道**。用配置的手机号账号加入频道，然后发送：

```text
/listen 频道链接
```

公开频道直接粘贴频道链接；私有频道用消息链接或邀请链接，`@用户名` 也认。

- **历史回填**：监听建立后自动下载频道的全部历史媒体帖，从旧到新按顺序。只想回填最近 N 条就在命令后带数字，比如 `/listen 频道链接 100`；`config/listening.json` 的 `history_limit` 也能全局控制，0 全部、-1 关闭、N 最近 N 条。回填和新帖走同一套过滤和去重，下载过的自动跳过。
- 新帖里的媒体自动下载到 `data/频道标题/` 文件夹，相册会在频道文件夹里再建子文件夹。
- **广告过滤**：类型白名单、最小大小、文案启发式三层判定，尽量不误杀；关键词和阈值在 `config/listening.json`，可以手动增删。
- **通知不打扰**：频道里不会出现机器人的消息；下载动态按频道聚合在管理员会话的一条摘要里持续累加，太长会自动另起一条，下载完的临时进度消息几秒后自动删除。
- 媒体全部由用户账号下载，最大 4GB，没有机器人接口的 20MiB 限制。
- `/listening` 打开监听面板：每频道一行，点频道名跳转、点「🚫 取消监听」停止。跳过的原因都会写进摘要和日志，方便调过滤规则。

## ✅ 已实现功能

**下载核心**

- **断点续传**：进程内失败续传，重启后恢复；短周期重试耗尽自动转长周期重试，5/15/30/60 分钟最多 4 轮；轮次用尽转冷驻留，断点和记录一直保留，连接恢复后自动继续，断网几天也不丢进度。手动停止会删除已下载内容，有意为之
- **失败自动重试**：超时、限流按退避重试，进程内直接续传
- **磁盘写满自护**：写盘遇到空间不足自动暂停队列并保留断点，通知管理员，清理后 `/resume` 从断点继续
- **队列管理**：`/queue` 查看排队、取消任务；`/pause` `/resume` 暂停恢复（停下进行中的任务并保留断点）
- **队列持久化**：任务实时落盘 `config/queue.json`，重启后自动恢复并续传
- **下载完成校验**：核对实际大小和 Telegram 报的大小，不一致按失败处理

**批量与自动化**

- **频道监听自动下载**：`/listen` 监听频道，新帖自动下载到独立文件夹；类型/大小过滤，关键词加正则组合规则识别广告和可疑文件；动态按频道聚合到管理员会话
- **跳过已存在文件**：同一文件再次发送会先确认；内容相同则下载后询问保留或删除
